## Stack

Next.js 16 (App Router, Turbopack, `src/` dir) · TypeScript · Tailwind CSS v4 · Better Auth · Drizzle ORM · Postgres on Neon. Package manager is npm. Import alias `@/*` → `src/*`.

Early-stage storefront: homepage and product pages read a Postgres catalog (products, categories, stock). Cart, checkout and sign-in are not built yet.

## Commands

```bash
npm run dev            # dev server
npm run build          # production build (needs DATABASE_URL, see below)
npm run lint           # ESLint (flat config, eslint-config-next)
npm run typecheck      # next typegen && tsc --noEmit
npm run auth:generate  # Better Auth CLI → writes tables to src/db/schema/auth.ts
npm run db:generate    # drizzle-kit: SQL migrations into ./drizzle
npm run db:migrate     # apply migrations
npm run db:push        # push schema directly (prototyping only)
npm run db:studio      # Drizzle Studio
npm run db:seed        # load/refresh the sample catalog (idempotent upserts by slug)
```

There is no test runner configured.

Plain `tsc` fails on `LayoutProps`/`PageProps`: these are global types generated by `next typegen`, so use `npm run typecheck`.

## Next.js 16 specifics

- Read the docs bundled in `node_modules/next/dist/docs/` before using Next APIs (see AGENTS.md); conventions differ from older versions.
- `next.config.ts` enables `cacheComponents` and `partialPrefetching`, which change how dynamic data and caching work in components.
- Request interception goes in `src/proxy.ts`; the `middleware` file convention is deprecated and was renamed to `proxy`.

## Architecture

**Database** (`src/db/`): `index.ts` exports a single `db`, a Drizzle client on Neon's serverless HTTP driver (`drizzle-orm/neon-http`) with the full schema attached. Every table lives in `src/db/schema/` and must be re-exported from `src/db/schema/index.ts`, because both drizzle-kit and the Better Auth adapter read that barrel.

**Auth** (`src/lib/`): `auth.ts` is the server-side Better Auth instance, using `drizzleAdapter(db, { provider: "pg", schema })`. The `nextCookies()` plugin must stay last in `plugins` so cookies set inside server actions are applied. `auth-client.ts` is the browser client (`better-auth/react`), pointed at `NEXT_PUBLIC_APP_URL`. All auth HTTP traffic goes through `src/app/api/auth/[...all]/route.ts` via `toNextJsHandler`.

**Adding Better Auth tables or plugins**: after changing auth config, run `npm run auth:generate`, make sure `src/db/schema/index.ts` has `export * from "./auth";`, then run `db:generate` and `db:migrate`.

## Database conventions

- **Scope.** The catalog is only `categories 1──< products 1──< product_images`. Carts, orders, payments, reviews, wishlists and product variants are deliberately out of scope for now, so ask before adding tables for them.
- **Stock is one `stock_quantity` per product.** Never store a stock status. Derive it with `toStock()` in `src/lib/catalog.ts`: 0 is sold out, up to `LOW_STOCK_THRESHOLD` shows "Only N left", anything higher is in stock. `sizes` is a plain `text[]` (`null` means one size) with no per-size stock until variants exist.
- **Money is integer cents** (`price_cents`, USD). `formatPrice()` takes cents. Never use floats for prices.
- **Schema style:** explicit snake_case column names, `integer` identity primary keys, unique `slug` as the lookup and upsert key, and `check` constraints for non-negative numbers.
- **Pages and components never import `db` or tables.** They read through `src/db/queries/*`, where every function starts with `"use cache"` + `cacheLife(...)` + `cacheTag("catalog")` (required under Cache Components; uncached reads break prerendering) and maps rows to the app types in `src/lib/catalog.ts`. After writing catalog data, call `revalidateTag("catalog")`.
- **No interactive transactions** on `neon-http`. Use `db.batch([...])` for atomic multi-statement writes.
- **Migrations:** edit the schema, run `db:generate`, review the SQL, then run `db:migrate`, and commit `drizzle/`. Never edit an applied migration. `db:push` is for throwaway experiments only.
- **Seeding:** `src/db/seed-data.ts` is the sample catalog. `db:seed` must stay idempotent (upsert by slug, replace child rows).
- **`next build` needs a migrated and seeded database**, because product pages are prerendered from it (`generateStaticParams` must return at least one slug).
- **Env:** `drizzle.config.ts` and `src/db/seed.ts` load env through `@next/env`, so `.env` and `.env.local` behave the same as in Next.

## Design system

Tailwind v4, CSS-first: there is no `tailwind.config`. `src/app/globals.css` imports `src/styles/tokens.css` (`@theme` tokens plus responsive `:root` variables), `base.css` (element defaults) and `components.css` (`@utility` primitives such as `btn-*`, `link`, `container-*`, `grid-products`, `media-product`, `scroller`, `caps`, `rule`). Use the tokens (`text-ink`, `bg-surface`, `text-h1`, `px-gutter`) rather than raw values or Tailwind's default palette. The aesthetic is monochrome with square corners (no border radius) and 1px hairlines. Headings use `font-display` (Bodoni Moda) at weight 400, and small UI labels use uppercase tracked text via `caps`. The site is light theme only. Fonts are loaded with `next/font` in `src/app/layout.tsx`.

## Environment

Copy `.env.example` to `.env.local` (or `.env`). Both are loaded by Next and by the `db:*` scripts. Variables: `DATABASE_URL` (Neon pooled URL), `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `NEXT_PUBLIC_APP_URL`. `.gitignore` ignores `.env*` except `.env.example`.
